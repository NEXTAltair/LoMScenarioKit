# コード・素材の由来の監査

確認日: 2026-10-01。対象は `2cd6ec7` までの履歴と、イベント画像の書き換え・公開準備を含む作業ツリー。初回調査で未比較だった公開ソースも取得し、結果を更新した。

## 結論

既知の参考元について、コード・サンプル素材・文書・依存 DLL・Git 履歴を一通り調べた。第三者 MOD のファイルや素材を丸ごと同梱したものは見つからなかった。ただし、次の対応関係はある。

| 区分 | 結果 | 公開前の扱い |
| --- | --- | --- |
| 他 MOD とのコード一致 | `MiniJson.cs` の JSON エスケープを処理する8つの case が `lom_modkit` と一致。周辺は異なる実装 | 定型処理の一致だけでは転用とは断定しない。参照元は MIT と確認できたので、参考元の記載を残す |
| 本編処理の再構成 | `StoryCharacters.LoadPortrait` / `RegisterSprite` に、本編の立ち絵登録と対応する手順が残る | 本編を参考にした箇所として明示。処理の複製をさらに減らすなら、画像供給を差し替えて本編の登録処理を呼ぶ方式へ変更する |
| Lua 実行フック | 本編・Binarizer・lom_modkit と共通する API 呼び出しがある。独自のシナリオ解決処理と組み合わせている | 外部 Lua を本編へ接続する互換処理として扱う。参考 MOD のフック全体を転載したとは確認できない |

## 個別の確認

### Lua 実行・Binarizer 互換処理

対象: `Patches.ExecuteLuaScriptPrefix`、`PatchBinarizerStoryRedirect`、`Endings.LoadOfficialScript`。

本編 `LuaManager.ExecuteLuaScript`、Binarizer の `HookCustomStory.LuaScriptRedirect`、lom_modkit の `LuaManagerPatch` を比較した。共通するのは `_luaEnvironment` の取得、`LoadLuaFunction`、`RunLuaFunction`、デバッグ用の `.LuaScript` 名など。本プロジェクトでは manifest によるイベント解決、訪問からの復帰、既読用テキスト変換、エンディング判定の挿入が前段にある。

Binarizer 側のスロット UI、ディレクトリ走査、コールバックによる脚本終了処理は持ち込まれていない。`Mortal.HookCustomStory`、`LuaScriptRedirect`、`mapStory` の名前は互換処理で直接参照する。方式や API 名の共通性は確認できるが、フック全体の転載を示す一致はない。

`Endings` は実行時に本編または導入済み MOD の Lua を読み、指定の分岐呼び出しの前へ追加コードを挿入する。本編 Lua 全文をソースや配布ファイルとして保存しているわけではない。固定のシナリオ ID と分岐呼び出し文字列はソースに含まれる。

### 立ち絵登録に残る対応関係

対象: `StoryCharacters.LoadPortrait`、`RegisterSprite`、`BeforeShow`。

本編 `StoryCharacterController.LoadPortrait` / `LoadPortraitSync` と、登録済み表情の確認 → 画像取得 → portraits への追加 → holder があるときの `AddPortraitObject` 呼び出し → 表情辞書への登録、という対応がある。読み込み先は自前 PNG、辞書操作と存在判定には差分がある。

したがって「本編の登録方法を参考にした短い再構成」と記録する。文字列一致がないことを理由に独立実装と断定しない。一方、立ち絵オブジェクトを組み立てる `AddPortraitObject` の本体は複製せず、本編のメソッドを呼んでいる。

向きの解決順序（指定値 → 現在値 → 既定値）も Fungus の扱いに合わせている。逆向き画像の検索・差し替え・反転取消は追加機能として実装されている。より保守的に処理の複製を減らす場合は、同期・非同期・一括読み込みでの画像供給を差し替え、本編の登録処理へ委譲する方法が候補になる。今回は調査のみで、この箇所は変更していない。

### JSON パーサーの一致

対象: `src/Shared/MiniJson.cs` の文字列エスケープ。

lom_modkit の同名ファイルと、引用符・逆斜線・スラッシュ・制御文字の8つの case が同じ並びで一致する。JSON が定める文字対応であり、短い定型処理でも一致し得る。

全体構造は異なり、本プロジェクトは Parser オブジェクトが位置を保持し、行・列つきのエラーを返す。比較先は文字列・位置・深さを関数引数で渡す。Unicode 変換、数値処理、リテラル判定にも差分がある。パーサー全体のコピーと断定する根拠にはしない。由来を最も保守的に扱う場合は、参考元の MIT 表示を添える選択ができる。

### 音声バンクと WAV

対象: `Audio/BankBuilder.cs`、`Audio/WavFile.cs`、`ScenarioAudio.cs`。

wwiser の `wparser.py`、関連定義、本編バンクの解析メモ、lom_modkit の `NativePcmPlayer` と比較した。

- `BankBuilder` は BKHD / DIDX / DATA / HIRC、Sound / Stop / Play / Event の配置を書き出す。バンク版140、プロジェクトID10403、言語ID、バス名、ビット値・項目順は参照元に依存する。
- wwiser は多数の版に対応する読み取りパーサー。本プロジェクトは必要な版・項目だけを生成する C# の書き出し処理で、パーサーの関数群・版分岐・実装そのものの移植は確認できない。
- 項目名やビットの説明には解析結果との共通性がある。由来を「無関係な完全独自形式」とは記載しない。
- WAV は RIFF のチャンクと PCM サンプルを読む。lom_modkit の waveOut 逐次再生・ミキサー・Ogg デコーダーは使っていない。こちらは全体を PCM16 へ変換し、Wwise バンクへ格納する。
- バンクへ入る音声は利用者の WAV から生成する。本編の BNK / WEM / 音声波形をリポジトリに保持したり、生成コードの配列として埋め込んだりしていない。

### サンプルとフォント

PNG は矩形・多角形・楕円・文字の描画、WAV は数式による波形合成で再生成できる。素材の全点一致は確認済み。ゲームの寸法や表示領域に合わせていることは、画像ファイルの転載とは区別する。

現在の画像を再現したフォントは Windows の `yumindb.ttf`（Yu Mincho Demibold）。[Microsoft のフォント一覧](https://learn.microsoft.com/en-us/typography/font-list/yu-mincho)でファイル名を確認した。[公式 FAQ](https://learn.microsoft.com/en-us/typography/fonts/font-faq)は、単語・文章を描画した PNG 等のゲーム同梱と、フォントファイルや再利用可能なビットマップフォントの再頒布を区別している。現在のサンプルは絵にラベルを描画した画像であり、字形を組み立てるフォントアトラスではない。生成環境の製品条件は適用され、フォント自体の権利を本プロジェクトのライセンスに含めない。

CSV・Lua・manifest の台詞、紹介、エンディング説明に、比較対象の文章と一致するものは見つからない。本編の場所名・キャラ名・敵アセット名・API 名は使う。12文字未満の定型文、翻案、未保存のゲーム本文まで非転用を証明する検査ではない。

## 同梱ライブラリと履歴

- 配布予定の第三者 DLL は制作ツール用の MoonSharp 2.0.0。NuGet の解決結果と配布スクリプトを確認し、ライセンス原文は `licenses/MoonSharp.txt`、説明は `THIRD-PARTY-NOTICES.md` にある。
- BepInEx、Harmony、Mono.Cecil、Unity、Addressables、Fungus、Wwise、Mortal 系 DLL は導入先の参照。プロジェクトでは `Private=false`、配布スクリプトでは必要な自前 DLL と MoonSharp を指定してコピーする。
- .NET Framework の参照アセンブリはビルド用途で、配布対象の DLL リストには入らない。Pillow は画像生成時の依存で、ゲーム向け ZIP に同梱しない。
- 利用者向け `pack` は利用者の `scenario/` を梱包するため、追加した素材の権利まで自動判定するものではない。
- 旧 `StoryPictures` は `0d22649` で追加され、後続履歴に残っている。作業ツリーの修正だけで、公開する Git 履歴から消えるわけではない。
- `StoryCharacters` と `MiniJson` は `9955a64` から存在する。現在の対象箇所を直す場合も、履歴公開の方針は別途扱う。
- 調査完了時点では LICENSE 未決定で、正式な配布 ZIP は未作成だった。その後の公開準備の方針は下記を参照。参考元への連絡は行っていない。
