# 001: 既存Rustエディターを制作GUIとCLIの共通基盤にする

- 日付: 2026-10-26
- 関連: #13
- 状態: 採用

## 背景

汎用の制作ツールに、既存エディターの編集機能と、ACで使っている資料・判定・コメント・履歴の機能が必要だった。UIはlom_modkitの既存画面を利用する。ACのWeb画面は移植しない。

## 決定

`tools/modkit` にlom_modkitのRustワークスペースを取り込み、元の章一覧・フォーム・プレビュー・フロー図へ「資料・添削・履歴」を加える。ACからは機能とデータの扱いを参考にし、HTML/CSSや専用ブラウザーサーバーは取り込まない。

保存処理を `lom-core::project_files` へ移し、GUIと `lomc agent` が `workspace_store` を通じて保存する。OSのファイルロック、内容のrevision、編集者付きの保存履歴を共通化する。コメントと判定はmanifestの編集用メタデータに保持し、章の復元と分ける。

LoMScenarioAddon向けのコンパイラーは `scenario_addon` に分ける。公式Lua APIへの変換を確認できるノードを実装し、未対応の種別・フィールドをエラーにする。既存MortalModHostコンパイラーと `.lommod` 処理は互換経路として保持する。AddonのプロジェクトからHostの導入・試遊処理は呼ばない。

## 上流との差分

取得元は `mohui666/lom_modkit` の `f7c20f8d37e0a03cb2ec0ca26a6b6261911d1e00`。`UPSTREAM.json` は取得時のファイルとハッシュを記録する。取り込み後のファイルが同じハッシュであることを意味しない。

追加した責務は添削データ、保存の競合検出と履歴、agent CLI、Addonコンパイラーである。元のGUI保存処理はcoreへ移し、editor側は再公開する。アプリ名・設定保存先・初期言語・Linuxのフォント候補も変更した。ゲーム本体のDLLや抽出素材、MortalModHostのC#実行環境は取り込んでいない。

## 影響と確認範囲

制作フォルダのバックアップには `.authoring` が必要になる。履歴は章・作品情報・添削を保存し、素材や資料の復元は扱わない。保存ロックはGUI・agent CLI間の競合を防ぐが、電源断時に複数ファイル全体を一括で戻す仕組みではない。

上流の回帰テスト、GUIのボタン操作、CLIのJSON入出力、GUIとCLIの保存競合を検証する。AddonのLuaはLoMScenarioToolでも構文を確認する。ゲーム内検証とWindowsの実機操作は今回の自動テストには含まない。
