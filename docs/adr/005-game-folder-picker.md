# ADR 005: ゲームフォルダーの選択をエディター内で行う

## 背景

上流GUIはゲームフォルダーの選択にrfdのOSダイアログを使う。Linuxの既定バックエンドはXDG Desktop Portalを必要とし、失敗するとzenityを試す。両方がないWSL環境では選択画面が表示されず、キャンセルと同じ`None`が返る。呼び出し側もそのまま戻るため、ボタンが反応しない。

## 決定と理由

ゲームフォルダーの選択は、eguiのモーダル画面で行う。パス入力、子フォルダーの一覧、親フォルダーへの移動、確定・キャンセルを提供する。OS側の追加インストールを前提にせず、キャンセルとダイアログ起動失敗を区別できないrfdへの依存もなくす。

「ゲームとMOD」「素材管理」と初回抽出を同じ選択画面に接続する。選択用途に応じた既存のゲーム・素材検証を維持し、検証と設定保存に成功した後でメモリー上の選択を更新する。`Mortal_Data`を選んだ場合はゲームルートへ揃える。初回抽出は確定後に開始し、キャンセルでは開始しない。

## 影響

ゲーム選択以外のファイル選択には上流のrfd経路が残る。新しい画面は既存のモーダル管理と5言語の翻訳に含め、フォルダー移動、可視ボタンからの表示、検証失敗、取消、設定保存をテストする。Windows・macOSでも同じ画面を使うが、今回の実画面検証はLinux/WSLで行う。
