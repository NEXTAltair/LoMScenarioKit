# 制作データとゲーム実行データを分け、GUIとCLIで共有する

日付: 2026-10-26。Issue: #9。

## 背景

LoMScenarioToolは既存シナリオの検査・配布を扱う。制作GUIはなく、作者はaddonLoMScenario-acで台本・資料・コメントを管理している。今回、作品を限定しないGUI・CLIをLoMScenarioKitへ追加するよう依頼された。

## 決定

AC側の行カード型エディタと共有保存を汎用化して、`tools/authoring/`へ置く。作品名・ルート名・話者候補は制作プロジェクトの`project.json`に移す。判定タグ、原稿、コメント、履歴、表記ルールは同じSQLiteに保存し、GUIとCLIが既存の更新番号による競合検査を共有する。ブラウザ内の一時データはプロジェクトごとに区別する。

CLIの操作一覧・入力仕様と実行結果をJSONで取得できるようにする。失敗は固定コードで区別し、次の操作候補は理由と引数配列で返す。

制作データはゲーム用`scenario/`の外に保存する。台本内の条件や演出は自由記述のため、実行用データへ自動変換しない。既存のC#ランタイム、LoMScenarioToolのcheck/packは引き続きゲーム用データを扱う。

## 理由と影響

AC側には添削、履歴、読み合わせが揃っている。現在の制作方法を移しやすく、Python標準ライブラリとブラウザで利用できる。lom_modkitのRustエディタを同時に導入すると、保存・実行形式の異なる編集環境が増えるため、この変更では導入しない。

原稿の構造検査はPythonとJavaScriptで整合させる必要がある。旧形式1の原稿・DBを読み、追加された判定タグは未判定として扱う。文書のMarkdownは読み取り専用。全イベントの発生順、ゲーム条件の評価、Lua生成、ACビューアのブラウザ内コメント移行は別途の実装が必要となる。
