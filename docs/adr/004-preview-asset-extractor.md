# ADR 004: プレビュー素材の抽出ツールを起動・配布工程に含める

## 背景

参考元のRust GUIには抽出ヘルパーを起動する処理があるが、こちらへの移植ではPythonの抽出処理とビルド・配置工程が抜けていた。そのためメニューは表示されても、コンポーネント不足で停止していた。

## 決定

参考元と同じ固定コミットから`preview_asset_worker.py`、`_probe_assets.py`、依存定義、PyInstallerのビルド処理とフックを取り込む。元の取得ハッシュとMIT許諾を保持する。解析処理は上流を維持し、ビルド作業先の明示指定とPython本体のライセンス収録を追加する。

`tools/build_editor.py`がCargoの出力先を調べ、そこに独立したPython環境を作る。入力ファイル・Pythonのバージョン・OS・CPUからビルド状態を判定し、必要なときだけヘルパーを作る。初回準備は`./editor`から行う。ビルドとself-checkが完了したフォルダーだけを配置し、失敗した場合は以前の成果物を残す。同時起動による準備の競合はファイルロックで防ぐ。

配布用コマンドは同じヘルパーとRustのreleaseビルドをまとめる。配布版にはPythonを含むため、利用者によるPythonの準備は不要になる。ゲームの画像は配布に含めず、初回使用時に手元のインストールから抽出する。

抽出設定とキャッシュは`LoMScenarioKit`専用の保存先を使う。旧エディターの設定は移行用に読み取れるが、書き換えない。既存の進捗・キャンセル・結果画面、完了後の読み込みと設定保存を利用する。

## 検証

上流の素材対応・部分失敗・既存キャッシュ保持テストに加え、初回準備、変更のない再起動、更新失敗時の保持、配置失敗時の復元、ソース配布の入力を確認する。実際のゲームから抽出し、GUIによる実行と背景・立ち絵の描画も確認する。ビルドと抽出はゲームを起動しない。
