# LoMScenarioKit

活俠傳 (Legend of Mortal) の追加キャラ・シナリオを制作し、ゲームに組み込むためのツールキットです。BepInEx 6 用アドオン **LoMScenarioAddon** と、検査・配布ツール **LoMScenarioTool** を含みます。ゲーム本体の DLL ファイルは変更しません。

追加キャラとの会話・好感度・場所イベント・決闘・エンディングなどに対応しています。同梱のシナリオは動作を試すためのサンプルです。

## 制作エディターを起動する

lom_modkitの既存Rust GUIを使って、章・ノード・プレビュー・フロー図を編集できます。資料検索、判定、コメントと返信、保存履歴を追加し、エージェント向けのJSON CLIと同じ制作フォルダを共有します。

```sh
./editor
```

Linux・macOS・WSLのターミナルから実行します。ソースからの起動にはRust・Cargo、Python 3.12以降、C++コンパイラーが必要です。初回はゲームのプレビュー素材を抽出するツールを専用環境に準備します。WSLでは起動に必要な描画設定を自動で適用します。

[起動・共同編集・書き出しの手順](docs/native-editor.md)を参照してください。

初めて使う場合は、**ファイル → サンプルから始める** を選んでください。趙活と大師兄の会話「裏山でひと休み」で、立ち絵・表情・BGM・選択肢を試せます。編集用コピーを作るので、台詞を変えてそのまま保存できます。[サンプルの使い方](tools/modkit/samples/first-scene/outline/guide.md)も用意しています。

## できること

シナリオと素材を用意することで、次の内容を追加できます。

| 分野 | 対応していること |
|---|---|
| キャラ | 複数キャラの追加、名前・肩書き・紹介カード・列伝、社交パネルへの表示 |
| 会話 | Lua シナリオ、立ち絵・表情差分・左右別の絵、既読色・既読スキップ |
| 好感度・保存 | 好感度の増減、追加キャラ・フラグのセーブとロード、周回の好感度引き継ぎ |
| イベント・分岐 | 場所イベントの抽選への追加、場所を選んだときのシナリオ差し替え、自前のフラグや好感度・日付などによる条件分岐 |
| 決闘 | 追加キャラを1対1の敵として登場させ、画像・台詞・能力値・行動の重み・天賦を設定、勝敗で分岐 |
| 天賦・秘笈 | 本編を元にした天賦・秘笈の追加、レベルごとの能力値や習得天賦の設定、既存の効果部品を組み合わせた新しい決闘効果 |
| エンディング | 本編の分岐への独自ルート追加、エンディングカード・列伝・汗青書への記録、死亡エンディング・奪命譜への記録 |
| 画像 | 背景・イベント CG・CG 画面の追加、結局CG の一覧への記録 |
| 音声 | WAV の曲・効果音・環境音の追加、ループ再生、音量設定・フェードへの対応 |
| 翻訳・配布 | 言語別テキストと既定言語へのフォールバック、制作ツールでのシナリオ検査・配布用 zip 作成 |

## できないこと・制約

| 項目 | 現在の制約 |
|---|---|
| 集団戦 | 追加キャラを集団戦（Battle）に登場させる機能は未対応 |
| 新しい戦闘動作 | 決闘の技・音・動作の部品は本編を流用。独自画像への差し替えには対応 |
| 主人公の絶招 | 秘笈から新しい絶招を習得させることはできない。天賦の付与には対応 |
| 圧縮音声 | OGG などは未対応。WAV を無圧縮で取り込むため、長い曲はメモリ使用量が増える |
| 場所選択時のシナリオ差し替え | 通常の行動へ進む場合だけ差し替え可能。本編のイベントへ進む場合は差し替えない |

定義方法と細かな制限は [シナリオ制作ガイド](docs/scenario-guide.md)、動作確認の環境・履歴は [開発メモ](docs/development.md) を参照してください。

## 導入

対象は Windows 版の活俠傳（Unity Mono・64bit）です。BepInEx 6 の **Unity Mono / Windows x64** 版を使います。

2026-10-16 に確認した導入済み環境は BepInEx `6.0.0-be.692`（commit `851521c`）、Unity `2020.3.49f1`、日本語化 MOD v2.5（runtime `2.5.52`、翻訳 `2026.10.15.378`）です。ゲームの Steam Build ID は `25957922` です。2.5.00 は現行ゲームのキャラ画像読み込み方式と、言語変更時の背景キャッシュ消去に対応しています。検証範囲と過去の確認履歴は [開発メモ](docs/development.md) を参照してください。日本語化 MOD なしでの動作確認は未実施です。

版番号は対応する日本語化 MOD の系列に合わせます。v2.5 向けは `2.5.00` から始め、アドオンだけの更新は `2.5.01`、`2.5.02` と末尾を増やします。日本語化 MOD v2.6 への対応時は `2.6.00` から始めます。

BepInEx 未導入の場合は、[公式ビルド配布ページ](https://builds.bepinex.dev/projects/bepinex_be) と [Unity Mono の導入手順](https://docs.bepinex.dev/v6.0.0-pre.1/articles/user_guide/installation/unity_mono.html) を参照し、ゲームフォルダに導入して一度起動します。すでに日本語化 MOD などで導入済みなら、その環境の版をログで確認してください。BepInEx 本体はこのアドオンの ZIP には含まれません。

1. ゲームを終了します。
2. 配布用の `LoMScenarioAddon-<版>.zip` を、`Mortal.exe` があるゲームフォルダに展開します。ソースから配布用 zip を作る場合は [ビルド手順](docs/development.md#ビルド) を参照してください。
3. 次の配置になっていることを確認して、ゲームを起動します。

```text
ゲームフォルダ/
  BepInEx/
    patchers/LoMScenarioAddon/LoMScenarioAddon.Patcher.dll
    plugins/LoMScenarioAddon/
      LoMScenarioAddon.dll
      scenario/
        scenario.json
        story/
        ...
  LoMScenarioTool/             シナリオ制作者用。遊ぶだけなら不要
  LoMScenarioAddon-docs/       説明書・ライセンス
```

## 更新・シナリオの入れ替え

1. ゲームを終了します。
2. 現在の `BepInEx/plugins/LoMScenarioAddon/`（自作シナリオを含む）をゲームフォルダの外へコピーして退避します。
3. ゲーム内の `BepInEx/patchers/LoMScenarioAddon/`、`BepInEx/plugins/LoMScenarioAddon/`、`LoMScenarioTool/`、`LoMScenarioAddon-docs/` を削除してから、新しい ZIP を展開します。これで旧版の素材が残るのを防げます。`BepInEx/config/lom.scenarioaddon.cfg` はそのまま使えます。
4. 自作シナリオを使う場合は、同梱の `scenario/` を削除して、退避した自作の `scenario/` をフォルダごと戻します。

シナリオだけを入れ替える場合も、退避後に `scenario/` をフォルダごと交換してください。読み込むシナリオフォルダは1つです。複数パックを上書きしても自動で統合されません。

## サンプルの遊び方

1. 自由行動で裏山の「修練」を選びます。イベント抽選で、試作キャラ2人の登場シナリオが発生します。登場イベントは一度きりです。
2. 出会った後に裏山をクリックすると、追加キャラとの訪問メニューが開きます。その場所で本編のイベントが始まる場合は、そちらへ進みます。
3. 訪問メニューから雑談や手合わせなどを試せます。

登場イベントは抽選です。同梱サンプルは確認しやすいよう重みを高く設定しています。
任意のシナリオを直接起動したい場合は、[確認用のキー操作](docs/scenario-guide.md#確認用のキー操作) を参照してください。

## 言語設定

初回起動後に作られる `BepInEx/config/lom.scenarioaddon.cfg` の `[Text]` で設定できます。編集はゲームを終了してから行ってください。

```ini
[Text]
Language = auto
```

- `auto`（既定）: 日本語化 MOD (`LOM_JP_StringVault`) があれば日本語、なければゲームの言語を使います。
- `ja`・`zh-TW`・`zh-CN`・`ko` など: 指定した言語に固定します。
- シナリオに訳がない項目は、そのシナリオの既定言語（指定がなければ日本語）で表示します。

## LoMアシスタントとの併用

2.5.03からLOMAssistant 2.6.1との任意連携に対応します。アシスタントがなくても動作します。

- 訪問イベントは通常行動の開始時に処理し、アシスタントが使う場所クリックの処理には割り込みません。
- アシスタントが候補一覧を作る前に追加イベントを登録し、追加シナリオのLua本文をプレビューへ渡します。公式シナリオはアシスタントの読み込みに任せます。
- アシスタントの画面・入力欄・キー設定を操作している間は、アドオンの確認用キーを抑えます。同じキーを両方に設定した場合もアシスタント側を優先します。キー設定自体は変更しません。

アシスタントのDLL・設定・ログ出力先は変更しません。連携先のAPIが変わった場合は専用ログに警告し、取得できない連携を見送ります。入力状態を読めない場合は、誤操作を避けるためアドオンの確認用キーを止めます。実ゲーム上の併用動作、アシスタントの随時セーブからの追加シナリオ復元は未検証です。

## ログ設定

2.5.02から、アドオンが出すログは次の専用ファイルに保存します。

- `BepInEx/LogOutput/LoMScenarioAddon/Addon.log`：プラグイン本体
- `BepInEx/LogOutput/LoMScenarioAddon/Patcher.log`：起動前のキャラID登録

初回起動後に作られる `BepInEx/config/lom.scenarioaddon.logging.cfg` を、ゲームを終了してから編集します。パッチャーとプラグインで同じ設定を使います。

```ini
[Logging]
Mode = Play
PlayFlushSeconds = 30
DebugFlushSeconds = 10
```

| モード | 記録する内容 | まとめて保存する間隔の既定値 |
|---|---|---|
| `Play` | 起動・登録・イベント開始などの通常情報、警告、エラー | 30秒 |
| `Debug` | Playの内容に加え、好感度・出会い状態の変化、訪問条件の不一致、既読用キーへの変換件数 | 10秒 |

間隔は1〜300秒の整数で設定できます。新しいログが無い間は書き込みません。エラー、正常終了、パッチャーの処理終了時は間隔を待たず保存します。待機中のログが約64Ki文字に達した場合も保存します。強制終了した場合、最後のまとめ保存からの記録が失われることがあります。

各ファイルは5MiBを超える前、または次の起動時に世代を切り替え、`.1`・`.2`の過去2世代を残します。極端に長い1件のメッセージは16Ki文字で省略し、`[truncated]`と記録します。

通常時、自作アドオンのメッセージは共通の`LogOutput.log`やUnityの`Player.log`には転送しません。専用ファイルへ保存できない場合は、理由を通知して、その起動中はBepInExのロガーへ切り替えます。BepInEx自身が出すプラグインの読み込み状況・例外などは、引き続き共通ログに出ます。

この設定は本体や日本語化MODのログには影響しません。`-nolog`はUnity全体のログ保存を止める別の設定で、アドオンの専用ログには影響しません。

## 動かないとき

まず上記の`Addon.log`と`Patcher.log`を確認してください。ファイルが作られない場合は、`BepInEx/LogOutput.log`の読み込みエラーや`Dedicated log`を含む行も確認します。
導入時はパッチャーとプラグインの両方が上記の場所にあり、`scenario/scenario.json` が配置されていることを確認します。
シナリオの定義や素材の検査には [LoMScenarioTool](docs/scenario-guide.md#作る人向けの道具-lomscenariotool) を使えます。

## 外し方

ゲームを終了して、次のフォルダを削除します。

- `BepInEx/patchers/LoMScenarioAddon/`
- `BepInEx/plugins/LoMScenarioAddon/`
- `LoMScenarioTool/`（導入している場合）
- `LoMScenarioAddon-docs/`（導入している場合）

設定と記録も不要なら、`BepInEx/config/lom.scenarioaddon.logging.cfg`と`BepInEx/LogOutput/LoMScenarioAddon/`も削除できます。

追加キャラを含むセーブをアドオンなしで読むと、そのキャラの ID は読み込み時に無視されます。
ただし、**追加した決闘の開始時に作られたオートセーブは、アドオンを外すと決闘設定が見つからず進行が止まる恐れがあります**。外す前に、決闘以外の場面で保存したセーブを用意してください。
