1. Open the sample

Change the first line of the sample to “Hello!”, play it, then save and reopen it. Start the editor before following these steps.

Screenshots use the Japanese interface. Click an image to enlarge it. Black bars hide personal paths and folder names.

1-1. Open File → Start from an example

Open File at the top and select the second item, Start from an example.

1-2. Check that the sample opened

The left list contains steps 01–17. A black preview background is normal before importing images. You are editing a separate copy of the sample.

Next: 2. Prepare preview images

2. Prepare preview images

2-1. Open the extraction command

Select File → Extract game preview assets. If backgrounds and characters already appear, go to step 3.

2-2. Choose the folder containing Mortal_Data

Enter your game installation path in Folder path and press Go. Check that Mortal_Data appears in the list, then press Use this folder. Your own path replaces the blacked-out area.

2-3. Wait for extraction

The progress dialog appears. Closing it to continue editing keeps extraction running. When it finishes, the result appears and images load automatically.

2-4. Check the background

Close the result and select step 01 on the left. The mountain background replaces the black preview.

More: change assets

For an existing extracted library, choose the whole folder containing preview_map.json and assets. An ordinary image folder is not a preview library.

Select Character, then Appearance, then Expression. Only expressions available for that appearance are listed. An unavailable expression returns to the normal expression when appearance changes. Hide the old character before showing a different base-game character appearance.

Import your own content

  1. Open Project assets under Assets.
  2. Import an image, character, or audio file.
  3. Select the imported content in a step’s form.
Local game preview images are not automatically included in exported projects. Game character and item names use their canonical names where no English game-name translation is supplied.

3. Change a line of dialogue

3-1. Select dialogue step 05 on the left

The Text field in the middle shows “趙活、こんな所にいたのか。”. Scroll the list to step 05 if needed.

3-2. Replace the text with “Hello!”

Click the Text field, select all its text and type Hello!. The dialogue in the preview also changes to Hello!.

4. Play and advance dialogue

4-1. Press Beginning below the preview

The position returns to 1 / 17. Your edited dialogue is retained.

4-2. Press Play

The scene advances through the background and character entrances, then waits at step 05, Hello!. BGM requires FFplay; allow time for the track to be prepared on first use.

4-3. Click the preview once

Step 06 appears: “少し風に当たりたくて。”. Dialogue waits for a click instead of advancing on a timer. The Next button also advances it.

More: playtest in the game

On Windows, Play or F5 validates the project and creates a separate temporary package for game testing. Configure the game under Game and Mods. Mac does not support game playtesting.

Check audio, filters, combat, and final timing in the game. Offline previews cannot reproduce every game effect.

5. Try a choice

5-1. Advance to the choices and select the lower button

From step 06, click the preview twice to reach step 08. Select the lower choice, “一緒に稽古する” (train together).

5-2. Check the selected branch

Step 11 shows “大師兄、お手柔らかに。”. To try the other branch, select step 08 on the left, then choose “少し休む” (rest).

More: configure choices, jumps, and endings

Without a jump, steps play in their listed order. Choices and conditional branches change the destination.

  1. Create the dialogue that follows each choice.
  2. Add a Choice node and set each option’s text and destination.
  3. Use F7 to check the flowchart, then test each route.

Ending a chapter

  • Leave Next chapter empty to return to free mode.
  • Select a next chapter to continue playing that chapter.
Standalone scene: Dialogue → End (Next chapter empty)
Continuing story: Dialogue → End (Next chapter selected)
A flag records an event such as meeting a character. Conditional branches can check that record later.

6. Save and reopen

6-1. Select File → Save all chapters

This saves your edited copy. You can also use Ctrl+S on Windows/Linux or ⌘S on macOS.

6-2. Check Saved in the bottom-left corner

Saved confirms that the changes are on disk. Before saving, they exist only in the open editor.

6-3. Reopen the same copy from Recent projects

Select File → Recent projects, then the first-scene-… copy you just saved. Start from an example creates another copy, so use Recent projects to continue this one.

6-4. Select step 05 and check for Hello!

Check both the Text field and the preview. You have now edited, played, saved and reopened the sample. Try your own line next. F6 checks the current chapter.

Show characters and write dialogue

  1. Add Show character before the dialogue.
  2. Choose a character, appearance, expression, position, and facing.
  3. Add Dialogue and select the same character.
  4. Use Hide character when the character leaves.

Dialogue and inner voice use a speaker. Narration does not need one. Imported voice lines are optional. Preview portraits require your locally extracted game assets.

Run several actions together

A Parallel actions group starts its actions together and continues when they all finish.

  1. Add a Parallel actions group.
  2. Add two Hide character actions, choosing a different character for each.
  3. Set both durations to 0.5 seconds and play the preview. Both characters fade out together.
Music, sounds, and looping effects count as complete when they start. Add Wait to keep the group active longer. Dialogue, choices, battles, jumps, and raw Lua belong outside the group.

Prepare a scene behind a black screen

  1. Add a Transition using Fade in to cover the screen.
  2. Change the background.
  3. Show the characters with zero fade and movement duration. Use a parallel group for several characters.
  4. Add a Transition using Fade out to reveal the scene.
Cover screen → Change background and place characters → Reveal screen → Dialogue
Fade in and Fade out describe the black overlay appearing and disappearing. Editor timing is a preview; check the actual result in the game.

Read check results

Read the conclusion first, then follow issues back to the affected steps. Expand Technical details to inspect the original report.

  • Status OK: the check found no issue.
  • Needs correction: fix the listed fields or story links.
  • Check in game: offline analysis cannot determine the result; this is not a pass.

F6 checks the current chapter. Use Release checks and packaging to check the whole project. Long operations can be hidden while you continue editing; reopen their progress from the bottom of the window.

Common terms

Form-based authoring does not require programming.

  • Node: one story step.
  • Flag: a record of whether an event happened.
  • Conditional branch: choose a destination using a record or number.
  • Asset library: images or other resources available to the editor.
  • Project package: an exported .lommod file.
  • Host: the component that loads a Mod into the game.
  • API: an interface used by scripts.
  • Lua: code the editor generates from your steps; normally you do not write it yourself.

Save, languages, and shortcuts

Open Settings with ⌘, on Mac or Ctrl+, on Windows/Linux. Choose Japanese, Simplified Chinese, Traditional Chinese, Korean, or English. The interface changes immediately and the choice is saved for the next launch.

Story translations are edited separately under Languages. Changing the interface language does not rewrite dialogue, names, comments, or IDs. Story translation languages remain those supported by the game runtime.

  • ⌘S / Ctrl+S: save.
  • F1: help.
  • F6: check current chapter.
  • F7: flowchart.
  • F5: Windows game playtesting.
  • Esc: close help or a dialog.
